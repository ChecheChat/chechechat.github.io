KOC 数字员工

2026.11 — 规划中做成工具讲出来给：泰国达人 BD 组

纯佣 KOC 量大、单个价值低，所以数字员工主做：写招募帖 → 发到 Facebook / LINE 群 → 达人填表 → 自动筛选打分 → LINE 官方号建联、发申样小程序 → 按规则批样 → 提醒发布 → 收视频、记履约 → 给客户周报。人只发 Facebook 帖、审核、处理例外。

KOC 建联跟 KOL 是两套逻辑：不是一对一谈，是在群里招募、一批批筛、一批批寄样、一批批催发布。人工跟不过来，而且泰国纯佣的接受度很低——一个客户三周没有达人接。所以这条线的设计是：重复的沟通全部交给数字员工，人只在「发帖、审帖、批例外、确认视频」四个点出手；任何谈价、合同、投诉、样品出问题，立刻转人。现在 SOP 写完待团队确认，LINE 官方号和申样小程序在准备。

怎么跑的（给想看细节的人）

人在哪里出手

数字员工
  • 收 brief、写帖、LINE 发帖、筛选打分、建联、批样、提醒、收视频、记履约、周报
  • 每天在客户群播报进度
人
  • BD：Facebook 发帖、回评论、处理「待人看」和转人工的对话
  • 组长：审帖、试跑期审名单和批样、确认视频、审周报
  • 商务负责人：定走 KOL 还是 KOC、谈预算合同

要先准备的东西

  • 公司 LINE 官方号（几个、叫什么）；公司 Facebook 主页能否进现有的招募群
  • TAP 申样小程序改成泰国可用版
  • 达人报名表、合作须知、话术库（发表单、催填、婉拒、通知、提醒）
  • 数字员工专区的电脑，24 小时开机
  • 第一个试跑的纯佣客户和产品

每周看什么

发帖次数 → 填表人数 → 通过人数 → 申样人数 → 按时发布人数；抽查出错数；客户追问进度的次数。

关键决定

  • KOL 和 KOC 分两套 SOP：一个是一对一谈，一个是批量招募，底层逻辑不一样，不硬合
  • 客户分级：重要、付费客户人跟；纯佣、低预算交数字员工
  • Facebook 不自动发：没有可用接口，自动发帖容易封号，人发、机器准备
  • 先全审再放权：试跑期人全看；连续 10 单（KOC 按 50 个达人算）没错改抽查；规则内自动通过
